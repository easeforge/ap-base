## 1. 概述

軟體弱點掃描（Vulnerability Assessment）是確保系統安全性的關鍵流程。本文件定義 Base AP 平台的完整弱掃流程，涵蓋靜態分析、動態測試、套件漏洞、機密洩漏四大面向。

### 掃描時機

| 時機 | 掃描項目 | 說明 |
|------|---------|------|
| 每次 commit / PR | SAST + SCA | 自動化於 CI/CD |
| 每次發版（Release） | 全項目掃描 | 發版前必須通過 |
| 每月定期 | SCA + DAST | 監控新發現的 CVE |
| 重大套件升級後 | SAST + SCA | 確認無新漏洞引入 |

## 2. 掃描範圍與分類

### 2.1 靜態應用程式安全測試 (SAST)

掃描程式碼本身的安全漏洞，不需執行程式。

| 掃描目標 | 檢查項目 |
|---------|---------|
| Python 後端 | SQL Injection、Command Injection、硬編碼密碼、不安全的加密、危險函式呼叫 |
| TypeScript 前端 | XSS（dangerouslySetInnerHTML）、eval()、不安全的正則表達式、敏感資料外洩 |

### 2.2 軟體組成分析 (SCA)

掃描第三方套件的已知漏洞（CVE）。

| 掃描目標 | 套件管理 |
|---------|---------|
| Python 後端 | pip (requirements.txt) |
| Node.js 前端 | npm (package.json / package-lock.json) |

### 2.3 動態應用程式安全測試 (DAST)

對執行中的應用程式進行黑箱掃描。

| 掃描目標 | 檢查項目 |
|---------|---------|
| API 端點 | 注入攻擊、認證繞過、未授權存取、CORS 設定、Header 安全性 |
| 前端頁面 | XSS、CSRF、點擊劫持、資訊洩漏 |

### 2.4 機密資訊掃描

掃描版本控制歷史中的密碼、API Key、Token 洩漏。

| 掃描目標 | 檢查項目 |
|---------|---------|
| Git 歷史 | 硬編碼密碼、API Key、連線字串、Private Key |
| 設定檔 | .env 是否進版控、預設密碼強度 |

## 4. 掃描流程

### 4.1 完整掃描流程圖

```
┌─────────────────────────────────────────────────────────┐
│                    軟體弱掃流程                           │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Step 1: 機密資訊掃描                                     │
│  ├── Gitleaks (Git 歷史)                                 │
│  └── 手動檢查 (.env, config, hardcoded secrets)           │
│           │                                              │
│           ▼                                              │
│  Step 2: 套件漏洞掃描 (SCA)                               │
│  ├── pip-audit (Python)                                  │
│  └── npm audit (Node.js)                                 │
│           │                                              │
│           ▼                                              │
│  Step 3: 靜態程式碼分析 (SAST)                             │
│  ├── Bandit (Python)                                     │
│  ├── Semgrep (Python + TypeScript)                       │
│  └── ESLint Security (TypeScript)                        │
│           │                                              │
│           ▼                                              │
│  Step 4: 動態安全測試 (DAST)                               │
│  ├── OWASP ZAP (API + 前端)                              │
│  └── 手動滲透測試 (認證/授權)                               │
│           │                                              │
│           ▼                                              │
│  Step 5: 報告彙整與修復                                    │
│  ├── 漏洞分級 (Critical/High/Medium/Low)                  │
│  ├── 修復優先順序                                          │
│  └── 驗證修復 (Re-scan)                                   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 4.2 各步驟詳細說明

#### Step 1: 機密資訊掃描

**目的**: 確保版本控制中沒有洩漏密碼、API Key 等機密資訊。

**優先執行原因**: 機密洩漏是最直接的安全風險，一旦推送到公開 repo 就無法撤回。

#### Step 2: 套件漏洞掃描

**目的**: 檢查第三方依賴是否有已知的 CVE 漏洞。

**處理原則**:
- Critical / High: 立即升級
- Medium: 評估影響後排程修復
- Low: 記錄追蹤
- 開發工具依賴（devDependencies）: 評估是否影響 production

#### Step 3: 靜態分析

**目的**: 在不執行程式的情況下，透過程式碼模式比對找出安全漏洞。

**重點檢查**:
- SQL 語句拼接（應使用參數化查詢）
- 使用者輸入未經驗證直接使用
- 硬編碼的密碼或金鑰
- 不安全的隨機數產生
- 危險的反序列化

#### Step 4: 動態測試

**目的**: 對執行中的系統進行黑箱測試，模擬攻擊者行為。

**測試場景**:
- 未認證存取受保護的 API
- SQL/NoSQL Injection
- XSS (Reflected + Stored)
- CSRF
- 認證 Token 偽造/重放
- 目錄遍歷
- HTTP Header 安全性

## 6. 執行指令手冊

### 6.1 環境準備

```bash
# 安裝掃描工具
cd Develop/backend
venv/Scripts/pip install bandit pip-audit semgrep

# Gitleaks (Windows)
# 從 https://github.com/gitleaks/gitleaks/releases 下載
# 放到 PATH 可存取的位置
```

### 6.2 Step 1: 機密資訊掃描

```bash
# Gitleaks — 掃描 Git 歷史
gitleaks detect --source . --report-path security-reports/gitleaks-report.json --report-format json

# 手動檢查 — 搜尋可能的硬編碼密碼
grep -rn "password\s*=\s*['\"]" --include="*.py" Develop/backend/app/
grep -rn "secret\|api_key\|token" --include="*.py" --include="*.ts" Develop/ | grep -v node_modules | grep -v ".env.example"
```

### 6.3 Step 2: 套件漏洞掃描

```bash
# Python 套件掃描
cd Develop/backend
venv/Scripts/pip-audit --format json --output ../../security-reports/pip-audit-report.json
# 預期結果: 0 known vulnerabilities

# Node.js 套件掃描
cd ../frontend
npm audit --json > ../../security-reports/npm-audit-report.json 2>&1
# 注意: react-scripts 間接依賴的漏洞屬開發工具，不影響 production
```

### 6.4 Step 3: 靜態程式碼分析

```bash
# Bandit — Python SAST
cd Develop/backend
venv/Scripts/bandit -r app/ -f json -o ../../security-reports/bandit-report.json

# 各嚴重度報告
venv/Scripts/bandit -r app/ -ll    # 只顯示 Medium 以上
venv/Scripts/bandit -r app/ -lll   # 只顯示 High 以上

# Semgrep — 多語言 SAST
cd ../..
semgrep scan --config auto Develop/backend/app/ --json --output security-reports/semgrep-backend-report.json
semgrep scan --config auto Develop/frontend/src/ --json --output security-reports/semgrep-frontend-report.json

# 特定規則集
semgrep scan --config p/python Develop/backend/app/
semgrep scan --config p/typescript Develop/frontend/src/
semgrep scan --config p/owasp-top-ten Develop/
```

### 6.5 Step 4: 動態安全測試

```bash
# 前提: 後端和前端服務已啟動
# 後端: http://localhost:10181
# 前端: http://localhost:10180

# OWASP ZAP — API 掃描（使用 Docker）
docker run -t ghcr.io/zaproxy/zaproxy:stable zap-api-scan.py \
  -t http://host.docker.internal:10181/openapi.json \
  -f openapi \
  -r zap-api-report.html

# OWASP ZAP — 全站掃描（使用 Docker）
docker run -t ghcr.io/zaproxy/zaproxy:stable zap-baseline.py \
  -t http://host.docker.internal:10180 \
  -r zap-baseline-report.html

# 手動測試清單
# □ 未登入直接存取 /api/users/ → 應回 401
# □ 用一般使用者存取 /api/sys_profiles/ → 應回 403
# □ 修改 JWT token 存取 API → 應回 401
# □ 不帶 X-Txn-Token 執行 PUT/DELETE → 應回 403
# □ SQL Injection: 在搜尋欄輸入 ' OR 1=1 -- → 不應洩漏資料
# □ XSS: 在通知說明輸入 <script>alert(1)</script> → 不應執行
```

### 6.6 一鍵完整掃描（Script）

```bash
#!/bin/bash
# security-scan.sh — Base AP 完整弱掃腳本

REPORT_DIR="security-reports"
mkdir -p $REPORT_DIR

echo "===== Step 1: 機密資訊掃描 ====="
gitleaks detect --source . --report-path $REPORT_DIR/gitleaks.json --report-format json 2>&1
echo ""

echo "===== Step 2: 套件漏洞掃描 ====="
echo "--- Python ---"
cd Develop/backend
venv/Scripts/pip-audit 2>&1 | tee ../../$REPORT_DIR/pip-audit.txt
echo ""
echo "--- Node.js ---"
cd ../frontend
npm audit 2>&1 | tee ../../$REPORT_DIR/npm-audit.txt
cd ../..
echo ""

echo "===== Step 3: 靜態分析 ====="
echo "--- Bandit (Python) ---"
cd Develop/backend
venv/Scripts/bandit -r app/ -ll 2>&1 | tee ../../$REPORT_DIR/bandit.txt
cd ../..
echo ""

echo "===== 掃描完成 ====="
echo "報告目錄: $REPORT_DIR/"
ls -la $REPORT_DIR/
```

## 7. CI/CD 整合建議

### 7.1 GitHub Actions 範例

```yaml
# .github/workflows/security-scan.yml
name: Security Scan

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  schedule:
    - cron: '0 2 * * 1'  # 每週一凌晨 2 點

jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0  # Gitleaks 需要完整歷史

      # 機密掃描
      - name: Gitleaks
        uses: gitleaks/gitleaks-action@v2

      # Python SAST + SCA
      - name: Python Security
        run: |
          cd Develop/backend
          pip install bandit pip-audit
          bandit -r app/ -ll
          pip-audit

      # Node.js SCA
      - name: npm audit
        run: |
          cd Develop/frontend
          npm ci
          npm audit --audit-level=critical
```

### 7.2 Gitea Actions 範例

```yaml
# .gitea/workflows/security.yml
name: Security Scan
on: [push, pull_request]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Python Audit
        run: |
          cd Develop/backend
          pip install pip-audit bandit
          pip-audit
          bandit -r app/ -lll
```

## 8. 報告與修復流程

### 8.1 漏洞分級標準

| 等級 | 定義 | 修復時限 | 範例 |
|------|------|---------|------|
| **Critical** | 可直接被攻擊利用，造成系統被接管或資料洩漏 | **24 小時內** | 硬編碼密碼洩漏、SQL Injection、RCE |
| **High** | 可被利用但需要特定條件 | **3 個工作天** | 認證繞過、XSS、CSRF |
| **Medium** | 需要進一步利用或影響有限 | **2 週內** | 資訊洩漏、DoS 可能、弱加密 |
| **Low** | 最佳實踐建議 | **下一版本** | 缺少安全 Header、開發工具漏洞 |

### 8.2 修復流程

```
發現漏洞 → 分級評估 → 建立 Issue → 修復開發 → 驗證掃描 → 合併發布
    │                                              │
    └── Critical: 立即通知團隊 ──────────────────────┘
```

### 8.3 報告範本

每次掃描後產出報告，包含：

```markdown
# 安全掃描報告 — YYYY-MM-DD

## 摘要
- 掃描時間: YYYY-MM-DD HH:MM
- 掃描版本: v1.0.0 (commit hash)
- 掃描工具: Bandit, pip-audit, npm audit, Gitleaks

## 結果總覽
| 等級 | 數量 | 已修復 | 待修復 |
|------|------|--------|--------|
| Critical | 0 | 0 | 0 |
| High | 0 | 0 | 0 |
| Medium | 0 | 0 | 0 |
| Low | 0 | 0 | 0 |

## 詳細發現
（列出每個漏洞的描述、影響、修復建議）

## 結論
□ 通過 — 可發布
□ 有條件通過 — 需修復 Critical/High 後發布
□ 未通過 — 需全面修復
```
