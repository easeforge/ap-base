## 1. 平台定位

### 目標

建立獨立的資安掃描平台，提供以下能力：

- **統一掃描入口**：所有開發專案在同一平台進行資安掃描
- **可追溯報告**：每次掃描產生完整報告，可回溯歷史
- **修補追蹤**：漏洞建立→指派→修補→驗證的完整閉環
- **持續監控**：自動化排程掃描，及時發現新漏洞

### 與開發環境的關係

```
開發者工作站                    Gitea (10.1.0.20)              掃描平台 (10.1.0.30)
┌──────────┐     push      ┌──────────────┐    Webhook     ┌──────────────────┐
│ 開發/測試  │ ──────────→ │  Git Repo     │ ──────────→  │ SonarQube        │
│           │              │  (原始碼)     │              │ DefectDojo       │
└──────────┘              └──────────────┘              │ Dependency-Track │
      ↑                                                  └──────────────────┘
      │          修補漏洞                    ↓
      └────────────────────────── 掃描報告/漏洞清單
```

### 設計原則

- **零侵入**：掃描平台獨立部署，不影響開發專案的程式碼和架構
- **零負擔**：開發專案不需安裝任何掃描工具
- **自動化**：透過 Webhook/排程觸發，減少人工介入
- **可追溯**：所有掃描結果、修補歷程完整留存

### 各元件角色

| 元件 | 角色 | 負責項目 |
|------|------|---------|
| **SonarQube** | 程式碼品質 + SAST | 靜態分析、程式碼異味、安全漏洞、覆蓋率 |
| **DefectDojo** | 漏洞管理中心 | 彙整所有掃描結果、追蹤修補狀態、產出報告 |
| **Dependency-Track** | SCA + SBOM | 套件漏洞監控、軟體物料清單、持續監控新 CVE |
| **掃描執行器** | 掃描引擎 | 執行實際的掃描工作，結果匯入管理平台 |

## 6. Gitea 整合設定

**Gitea → Settings → Webhooks → Add Webhook**

| 設定 | 值 |
|------|-----|

| HTTP Method | POST |
| Content Type | application/json |
| Secret | `your-webhook-secret` |
| Events | Push, Pull Request |

### 6.2 掃描觸發 API（自建）

建立一個簡單的掃描觸發服務，接收 Webhook 後執行掃描：

```python
# scan-trigger/app.py
"""
掃描觸發服務 — 接收 Gitea Webhook，觸發對應的掃描流程
"""

from fastapi import FastAPI, Request, BackgroundTasks
import subprocess
import json
import os

app = FastAPI(title="Security Scan Trigger")

WORKSPACE = "/workspace"
REPORTS = "/reports"

@app.post("/api/scan/trigger")
async def trigger_scan(request: Request, background_tasks: BackgroundTasks):
    """接收 Gitea Webhook，背景執行掃描"""
    payload = await request.json()

    repo_name = payload.get("repository", {}).get("name", "")
    repo_url = payload.get("repository", {}).get("clone_url", "")
    branch = payload.get("ref", "refs/heads/main").split("/")[-1]
    commit = payload.get("after", "")[:8]

    if not repo_url:
        return {"error": "No repository URL"}

    # 背景執行掃描
    background_tasks.add_task(
        run_scan, repo_name, repo_url, branch, commit
    )

    return {
        "message": f"Scan queued for {repo_name}:{branch}",
        "commit": commit
    }

async def run_scan(repo_name: str, repo_url: str, branch: str, commit: str):
    """執行完整掃描流程"""
    scan_dir = f"{WORKSPACE}/{repo_name}"
    report_dir = f"{REPORTS}/{repo_name}/{commit}"
    os.makedirs(report_dir, exist_ok=True)

    # 1. Clone/Pull 原始碼
    if os.path.exists(scan_dir):
        subprocess.run(["git", "-C", scan_dir, "fetch", "--all"], check=True)
        subprocess.run(["git", "-C", scan_dir, "checkout", branch], check=True)
        subprocess.run(["git", "-C", scan_dir, "pull"], check=True)
    else:
        subprocess.run(["git", "clone", "-b", branch, repo_url, scan_dir], check=True)

    # 2. Gitleaks — 機密掃描
    subprocess.run([
        "gitleaks", "detect",
        "--source", scan_dir,
        "--report-path", f"{report_dir}/gitleaks.json",
        "--report-format", "json"
    ])

    # 3. Bandit — Python SAST
    backend_dir = f"{scan_dir}/Develop/backend/app"
    if os.path.exists(backend_dir):
        subprocess.run([
            "bandit", "-r", backend_dir,
            "-f", "json",
            "-o", f"{report_dir}/bandit.json"
        ])

    # 4. SonarScanner — 送到 SonarQube
    subprocess.run([
        "sonar-scanner",
        f"-Dsonar.projectKey={repo_name}",
        f"-Dsonar.sources={scan_dir}/Develop",
        f"-Dsonar.host.url=http://sonarqube:9000",
        f"-Dsonar.token={os.environ.get('SONAR_TOKEN', '')}"
    ])

    # 5. pip-audit — Python SCA
    req_file = f"{scan_dir}/Develop/backend/requirements.txt"
    if os.path.exists(req_file):
        subprocess.run([
            "pip-audit", "-r", req_file,
            "--format", "json",
            "--output", f"{report_dir}/pip-audit.json"
        ])

    # 6. 匯入 DefectDojo
    # 透過 DefectDojo API 匯入各工具的掃描結果
    import_to_defectdojo(repo_name, commit, report_dir)

def import_to_defectdojo(repo_name, commit, report_dir):
    """將掃描結果匯入 DefectDojo"""
    import requests

    dd_url = "http://defectdojo-web:8080/api/v2"
    dd_token = os.environ.get("DD_API_TOKEN", "")
    headers = {"Authorization": f"Token {dd_token}"}

    # 匯入各工具的報告
    scan_types = {
        "gitleaks.json": "Gitleaks Scan",
        "bandit.json": "Bandit Scan",
        "pip-audit.json": "pip-audit Scan",
    }

    for filename, scan_type in scan_types.items():
        filepath = f"{report_dir}/{filename}"
        if os.path.exists(filepath):
            with open(filepath, "rb") as f:
                requests.post(
                    f"{dd_url}/import-scan/",
                    headers=headers,
                    data={
                        "scan_type": scan_type,
                        "engagement": 1,  # 需要先建立 engagement
                        "verified": False,
                        "active": True,
                    },
                    files={"file": f}
                )
```

## 7. 掃描工作流程

### 7.1 自動掃描流程（Webhook 觸發）

```
開發者 push 程式碼到 Gitea
        │
        ▼
Gitea Webhook → 掃描觸發 API
        │
        ▼
┌── 掃描執行器 ──────────────────────────────┐
│                                            │
│  1. git clone/pull 最新程式碼                │
│  2. Gitleaks → 機密掃描                     │
│  3. Bandit → Python SAST                   │
│  4. SonarScanner → 送到 SonarQube           │
│  5. pip-audit / npm audit → SCA             │
│  6. syft → 產生 SBOM → Dependency-Track     │
│  7. 結果匯入 DefectDojo                     │
│                                            │
└────────────────────────────────────────────┘
        │
        ▼
DefectDojo 產生漏洞清單
        │
        ▼
通知開發者（Email / Slack / Webhook）
```

### 7.2 手動掃描流程

1. 登入 DefectDojo (`https://scan.internal/defectdojo`)
2. 選擇或建立 Product（對應專案）
3. 建立 Engagement（掃描批次）
4. 上傳掃描報告 或 觸發自動掃描
5. 檢視漏洞清單

## 8. 漏洞追蹤與修補流程

### 8.1 完整閉環流程

```
    掃描發現漏洞
         │
         ▼
  ┌─── DefectDojo ───┐
  │                   │
  │  自動建立漏洞      │
  │  ├── 分級          │──→ Critical: 立即通知
  │  ├── 指派負責人    │──→ High: 3天內修補
  │  └── 設定期限      │──→ Medium: 2週內修補
  │                   │
  └───────┬───────────┘
          │
          ▼
    開發者修補程式碼
          │
          ▼
    Push 到 Gitea
          │
          ▼
    Webhook 觸發重新掃描
          │
          ▼
  ┌─── DefectDojo ───┐
  │                   │
  │  比對新舊掃描結果   │
  │  ├── 漏洞已消失    │──→ 自動標記「已修復」
  │  ├── 漏洞仍存在    │──→ 保持「待修補」
  │  └── 新增漏洞      │──→ 建立新漏洞
  │                   │
  └───────────────────┘
          │
          ▼
    所有漏洞修復 → 發布版本
```

### 8.2 DefectDojo 漏洞狀態

| 狀態 | 說明 |
|------|------|
| **Active** | 新發現，待處理 |
| **Verified** | 經確認為真實漏洞 |
| **Mitigated** | 已修補，待驗證 |
| **False Positive** | 誤報，標記忽略 |
| **Out of Scope** | 不在修補範圍 |
| **Risk Accepted** | 已知風險，接受不修補 |

### 8.3 通知機制

DefectDojo 支援以下通知：

| 通知方式 | 設定位置 |
|---------|---------|
| Email | System Settings → Email |
| Slack | System Settings → Slack Webhook |
| Microsoft Teams | System Settings → MS Teams Webhook |
| Webhook | System Settings → Webhook URL |

## 10. 維運管理

### 10.1 啟動/停止

```bash
# 啟動平台
cd /opt/security-platform

# 停止平台

```

### 10.2 初始設定

| 步驟 | 操作 |
|------|------|
| 1 | 啟動 `docker compose up -d`，等待初始化完成（約 3-5 分鐘） |
| 2 | SonarQube: 訪問 `http://IP:9000`，預設帳密 admin/admin，首次登入強制改密碼 |
| 3 | SonarQube: 安裝語言插件（Python, TypeScript, JavaScript） |
| 4 | SonarQube: 建立 Project，取得 Token |
| 5 | DefectDojo: 訪問 `http://IP:8080`，預設帳密 admin/admin |
| 6 | DefectDojo: 建立 Product Type → Product → Engagement |
| 7 | DefectDojo: 取得 API Token（用於自動匯入） |
| 8 | Dependency-Track: 訪問 `http://IP:8082`，建立 Project |

### 10.3 備份策略

```bash
# 每日備份資料庫
docker compose exec postgres pg_dumpall -U postgres > backup/db_$(date +%Y%m%d).sql

# 備份 Volume 資料
tar czf backup/volumes_$(date +%Y%m%d).tar.gz data/
```

### 10.4 更新策略

```bash
# 拉取最新映像檔
docker compose pull

# 重啟（保留資料）
docker compose up -d
```
