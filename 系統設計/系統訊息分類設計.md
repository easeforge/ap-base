# 系統訊息代碼設計規格

## 1. 概述

系統訊息代碼（System Message Codes）為 Base AP 後臺管理基底平台的統一訊息管理機制，將所有系統回應訊息（成功、錯誤、警告、提示等）以代碼化方式進行集中管理，並透過 `system_codes` 資料表依語系提供多語系翻譯。

### 1.1 設計目標

- 所有系統回應訊息統一編碼管理，不在程式中硬編碼訊息文字
- 依語系自動翻譯，前端依使用者語系顯示對應訊息
- 正式環境與開發測試環境回傳不同精細度的訊息，兼顧安全性與除錯效率
- 透過系統代碼管理介面即可維護，無需修改程式碼

## 2. 代碼編碼規則

### 2.1 代碼格式

```
┌─────────┐┌────┐┌────────┐
│ PREFIX  ││分類碼││ 訊息碼  │
│  3 碼   ││ 2碼 ││  4 碼   │
└─────────┘└────┘└────────┘

範例：ERR010001
      ├─┤├┤├──┤
       │  │   └── 訊息流水號：0001
       │  └────── 分類碼：01（認證/登入）
       └───────── 前綴：ERR（錯誤）
```

**代碼總長度：9 碼**（前綴 3 碼 + 分類碼 2 碼 + 訊息碼 4 碼）

### 2.2 前綴定義（PREFIX）

| 前綴 | 說明 | 用途 |
|------|------|------|
| `SYS` | 系統訊息 | 系統狀態、成功回應、一般提示 |
| `ERR` | 錯誤訊息 | 操作失敗、驗證錯誤、例外狀況 |
| `DAT` | 資料處理 | 匯入匯出、資料驗證、批次處理結果 |

### 2.3 分類碼區間定義

分類碼以 2 位數字表示，依環境區分為兩個區間：

#### 正式環境（01~49）

正式環境的訊息**不揭露系統內部細節**，以安全、簡潔為原則。

| 分類碼 | 模組 | 說明 |
|--------|------|------|
| 01 | 認證/登入 | 登入驗證、CAPTCHA、Session 相關 |
| 10 | 使用者/組織管理 | 帳號、角色、組織 CRUD 相關 |
| 20 | 系統管理/設定 | 系統設定、代碼管理、功能管理 |
| 30~49 | 應用功能（預留） | 未來應用專案擴充使用 |

#### 開發測試環境（50~99）

開發環境的訊息**包含詳細的技術細節**，方便開發人員定位問題。

| 分類碼 | 模組 | 對應正式碼 | 說明 |
|--------|------|-----------|------|
| 51 | 認證/登入（開發） | 01 | 含帳號、hash 比對、Redis Session 細節 |
| 60 | 使用者/組織管理（開發） | 10 | 含 SQL 錯誤、欄位驗證細節 |
| 70 | 系統管理/設定（開發） | 20 | 含設定載入、檔案同步細節 |
| 80~99 | 應用功能（開發預留） | 30~49 | 未來應用專案擴充使用 |

**正式與開發的對應關係：分類碼差 50**（01↔51、10↔60、20↔70、30↔80）

## 4. 資料儲存方式

### 4.1 system_codes 欄位對應

使用 `system_codes` 資料表儲存，欄位對應如下：

| system_codes 欄位 | 用途 | 範例 |
|-------------------|------|------|
| `code_type` | 固定值 | `sys_message_code` |
| `code_type_name` | 類別名稱（JSONB） | `{"zh-TW":"系統訊息代碼","zh-CN":"系统讯息代码","en":"System Message Codes"}` |
| `code` | 訊息代碼 | `ERR010001` |
| `code_name` | 訊息內容（JSONB 多語系） | `{"zh-TW":"帳號或密碼錯誤","zh-CN":"帐号或密码错误","en":"Invalid account or password"}` |
| `order` | 排序 | 依代碼數值排序 |
| `is_active` | 啟用狀態 | `TRUE` |
| `note1` | 環境標記 | `production` / `development` |
| `note2` | 對應開發代碼（正式用） | `ERR510001`（僅正式碼填寫，方便交叉查詢） |

### 4.2 分類說明儲存

訊息分類定義也存入 `system_codes`，使用獨立的 code_type：

| system_codes 欄位 | 用途 | 範例 |
|-------------------|------|------|
| `code_type` | 固定值 | `sys_message_category` |
| `code_type_name` | 類別名稱（JSONB） | `{"zh-TW":"系統訊息分類","zh-CN":"系统讯息分类","en":"System Message Categories"}` |
| `code` | 分類碼 | `01` |
| `code_name` | 分類說明（JSONB 多語系） | `{"zh-TW":"認證/登入","zh-CN":"认证/登入","en":"Authentication/Login"}` |
| `note1` | 環境標記 | `production` / `development` |

## 5. 參數替換機制

### 5.1 概述

訊息內容支援 `{參數名}` 佔位符，前端在顯示時將佔位符替換為實際值，讓同一組代碼可適用於不同功能模組的回應。

### 5.2 code_name 定義方式

在 `system_codes` 的 `code_name` JSONB 中使用 `{參數名}` 佔位符：

```json
{
  "zh-TW": "{name}儲存成功",
  "zh-CN": "{name}储存成功",
  "en": "{name} saved successfully"
}
```

### 5.3 前端呼叫方式

```typescript
// 帶入參數物件，替換訊息中的佔位符
getMessageByCode("SYS100001", { name: "使用者設定" })
// → 系統訊息：(SYS100001)使用者設定儲存成功

getMessageByCode("DAT100001", { name: "國家代碼", count: "249" })
// → 系統訊息：(DAT100001)國家代碼匯入成功，共 249 筆
```

### 5.4 常用參數名稱規範

| 參數名 | 說明 | 範例 |
|--------|------|------|
| `{name}` | 功能名稱/資料名稱 | 使用者設定、系統代碼 |
| `{count}` | 數量 | 249 |
| `{row}` | 列號 | 15 |
| `{detail}` | 細節說明（開發環境用） | column 'email' is null |
| `{id}` | 資料識別碼 | 1024 |

## 6. 後端回傳機制

### 6.1 環境判斷邏輯

後端依 `.env` 中的 `ENVIRONMENT` 設定決定回傳哪一組代碼：

```python
# 虛擬碼
if settings.ENVIRONMENT == "production":
    # 正式環境：回傳分類碼 01~49 的代碼
    raise HTTPException(status_code=401, detail="ERR010001")
else:
    # 開發環境：回傳分類碼 50~99 的代碼（含詳細資訊）
    raise HTTPException(status_code=401, detail="ERR510001")
```

### 6.2 API 回傳格式

```json
{
  "detail": "ERR010001"
}
```

前端收到代碼後，透過 `GET /api/system/message-codes?lang=zh-TW` 取得的對應表進行翻譯顯示。

## 7. 前端顯示機制

### 7.1 訊息代碼載入

前端在 `SystemContext` 初始化時，從公開端點 `GET /api/system/message-codes` 載入所有啟用的訊息代碼對應表，並隨語系切換時重新載入。

### 7.2 統一顯示格式

所有系統訊息統一以下列格式呈現：

```
系統訊息：(代碼)說明
```

各語系範例：

| 語系 | 顯示內容 |
|------|---------|
| zh-TW | `系統訊息：(ERR010001)帳號或密碼錯誤` |
| en | `System Message: (ERR010001) Invalid account or password` |
| zh-CN | `系统讯息：(ERR010001)帐号或密码错误` |

### 7.3 訊息顯示流程

```
後端回傳 detail: "ERR010001"
        ↓
前端呼叫 getMessageByCode("ERR010001")
        ↓
查詢 sys_message_code 對應表取得說明
        ↓
組合格式：{系統訊息標籤}：({代碼}){說明}
        ↓
顯示：「系統訊息：(ERR010001)帳號或密碼錯誤」
```

### 7.4 Fallback 機制

若代碼在對應表中找不到，顯示格式為：`系統訊息：(ERR010001)ERR010001`，保留原始代碼確保訊息不遺失。

## 8. 管理方式

- 透過**系統代碼設定**頁面管理，code_type 選擇 `sys_message_code`
- 新增訊息代碼時依編碼規則填入代碼、多語系訊息內容、環境標記
- 停用代碼設定 `is_active = false`，不需刪除
- 分類定義透過 code_type = `sys_message_category` 管理

## 9. 注意事項

1. **安全性**：正式環境嚴禁回傳含有系統內部資訊的開發代碼（50~99 區間）
2. **一致性**：同一個錯誤情境在正式環境和開發環境應各有一組對應代碼
3. **擴充性**：新增模組時，選擇未使用的分類碼區間，正式碼和開發碼各取對應區間
4. **代碼不複用**：已廢棄的代碼應停用而非刪除，不得將代碼重新指派給其他訊息
