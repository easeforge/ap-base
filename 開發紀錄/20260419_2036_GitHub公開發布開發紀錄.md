## 五、SSH Key 設定（每服務獨立）

### 5.1 設計：不重用 Gitea 的 key

原本 `~/.ssh/id_ed25519` 是給 Gitea/NAS 用的。**不直接拿來給 GitHub**，理由：

- 任一服務 key 外洩，影響範圍可獨立
- 撤銷 GitHub 那把不會影響 Gitea 部署

### 5.2 產生專用 key

```bash
ssh-keygen -t ed25519 -C "porsche.chen@gmail.com (github)" \
  -f ~/.ssh/id_ed25519_github -N ""
```

### 5.3 SSH config 自動分流

`~/.ssh/config`：

```ssh-config
# GitHub - dedicated key
Host github.com
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_github
    IdentitiesOnly yes

# Gitea on NAS - existing key
Host git.lab.taipei
    HostName git.lab.taipei
    User git
    Port 2222
    IdentityFile ~/.ssh/id_ed25519
    IdentitiesOnly yes
```

> `IdentitiesOnly yes` 強制只試指定 key，避免 SSH agent 把錯的 key 給對方（會導致 `Too many authentication failures`）。

### 5.4 公鑰加到 GitHub

`https://github.com/settings/ssh/new` → 標題 `Windows-Dev-Claude` → 貼公鑰。

驗證：

```bash
$ ssh -T git@github.com
Hi porsche5130! You've successfully authenticated, but GitHub does not provide shell access.
```

## 六、Push Mirror：Gitea → GitHub

### 6.1 設計

工作流：**只推到 Gitea，GitHub 由 mirror 自動同步**

好處：
- 單一寫入點，避免兩邊不一致
- Gitea 留作主開發環境（私網、含 PR / Discussion / wiki）
- GitHub 對外公開、收 issue / star

### 6.2 Gitea 設定

`https://git.lab.taipei/porsche/ap-base/settings` → Mirror Settings → Add Push Mirror

| 欄位 | 值 |
|------|---|
| URL | `https://github.com/easeforge/ap-base.git` |
| Username | `porsche5130` |
| Password | GitHub PAT（Fine-grained, repo scope, contents=write） |
| Sync Interval | `1h0m0s` |

### 6.3 ⚠️ Force-push 翻車事故（重要教訓）

**事發經過**：

1. 我直接 `git push github main` 推到 GitHub（包含 EaseForge 改名 commit）
2. GitHub `main` = `9a070fb` ✅
3. 用戶觸發 Gitea push-mirror 同步
4. **Gitea 用 force-push 把它的 `main`（停在 `50d2b3c`）覆蓋上去**
5. GitHub 的 `9a070fb` 不見了 ❌

**根本原因**：Push mirror 為了確保鏡像端與來源端完全一致，預設使用 force-push。**任何不在 Gitea 上的 commit 都會被擦掉**。

**修正**：
```bash
git push origin main   # 把缺的 commit 補回 Gitea
# 等 mirror 同步（或手動觸發）
```

**從此規則**：
- ✅ 只 `git push origin main`（Gitea）
- ❌ 不要 `git push github main`（直推 GitHub）
- 例外：要在 GitHub 上做改動（例如 web UI 編輯 README），完成後立刻把 commit `git pull` 回本機並 `push origin main`，避免下次 mirror 同步把它擦掉

```
└── PULL_REQUEST_TEMPLATE.md             ← PR checklist
```

### 7.2 設計重點

**CONTRIBUTING.md**：

- 雙語接受（英文 / 繁中）
- branch 命名規則（`fix/`、`feat/`、`refactor/`、`docs/`、`chore/`）
- Conventional Commits（loose）
- 明確區分 CE / EE 範圍，避免社群提的 PR 落到 EE 區
- 後端：禁 `print()`，禁硬編碼字串（走 message code）
- 前端：禁 `alert()`，禁硬編碼顯示文字（走 i18n）

**SECURITY.md**：

- 私下回報信箱：`porsche.chen@gmail.com`
- Subject prefix：`[SECURITY] Base AP — <description>`
- 處理時程承諾（acknowledge 3 天 / 評估 7 天 / 修復依嚴重度）
- 範圍清楚標示（in/out scope）
- 部署 hardening 建議

**Issue 模板**：

- Bug：版本/環境表格、重現步驟、checklist
- Feature：問題敘述、提議、CE/EE 範圍勾選
- `config.yml` 關閉空白 issue，把問題引導到 Discussions、安全議題引導到 SECURITY.md
