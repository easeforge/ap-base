## 修正項目

### 1. 系統代碼排序 DOM 衝突修正

**Commit**: `aa29f59`（合併於 zh-CN commit）

**問題**: 點擊「次序」欄位排序時，瀏覽器報錯 `NotFoundError: Failed to execute 'removeChild' on 'Node'`

**原因**: `dangerouslySetInnerHTML` 產生的 DOM 節點不受 React 管控，排序時 React reconciliation 嘗試重用/移除節點失敗

**修正**: 
- 移除表格中所有 `dangerouslySetInnerHTML` / `renderHTML()`
- 改為純文字顯示（代碼類別名稱、代碼名稱、代碼編號）

### 2. 系統代碼表單欄位排列修正

**Commit**: `aa29f59`

**修正前**: 欄位順序混亂，排列次序欄位顯示「木材」（翻譯錯誤）

**修正後排列**:
1. 代碼類別識別碼（full-width + datalist）
2. 代碼類別名稱(zh-TW) | 代碼類別名稱(en)
3. 代碼編號 | 排列次序
4. 代碼名稱(zh-TW) | 代碼名稱(en)
5. 說明1~5（並排）+ 啟用

### 3. 新增簡體中文語系 (zh-CN)

**Commit**: `aa29f59`

- 使用 `opencc-python-reimplemented` 從 zh-TW 翻譯檔自動繁簡轉換
- 建立 `src/locales/zh-CN/translation.json`（475 keys）
- `i18n.ts` 加入 zh-CN 靜態 fallback
- 資料庫新增：
  - `sys_languages`: zh-CN 記錄 + lang_data
  - `system_codes`: Language 代碼 zh-CN（short_name: 简中）
  - `sys_profiles.sys_languages`: 加入 zh-CN
- JSONB 多語系欄位補值：所有 5 張表 1791 rows（從 zh-TW 繁簡轉換）

### 4. 基礎語系改為英文

**Commit**: `2aadc09`

**變更**:
- `getI18nValue()` fallback 從 `field['zh-TW']` 改為 `field['en']`
- 新增 `BASE_LANGUAGE = 'en'` 匯出常數
- `i18n.ts` fallbackLng 從 `'zh-TW'` 改為 `'en'`

**設計理念**: 程式撰寫以英文為基礎表達語系，缺值時以英文填充

### 5. 多語系表單改為動態依啟用語系產生

**Commit**: `0d80236`

**問題**: 表單中多語系輸入欄位寫死 zh-TW 和 en 兩個，啟用 zh-CN 後缺少第三個

**修正**: 4 個頁面全面改為 `enabledLangs.map()` 動態產生：
- `SystemCodesPage` — code_type_name、code_name
- `SystemFunctionsPage` — func_name
- `UserRolesPage` — role_name
- `SystemNotificationsPage` — notice_subject、notice_description

同時修正：
- 代碼類別顯示：上方當前語系名稱，下方基礎語系(en)名稱
- DataTable 新增「代碼類別識別碼」欄位

### 6. 補齊多語系表單缺少的翻譯 key

**Commit**: `25625ae`

**問題**: 簡體中文介面中部分 label 顯示繁體字（因為翻譯 key 不存在，fallback 到程式碼中的繁體中文預設值）

**修正**: 3 個語系檔各新增 10 個翻譯 key：
- `systemCodes`: codeType, codeTypeName, codeName
- `sysFunctions`: funcName
- `userRoles`: roleName
- `system_notifications`: noticeSubject, noticeDescription
- `sysProfile`: sysTitle, sysCopyright, languageSettings 等

### 7. 語系翻譯 key 同步補足功能

**Commit**: `8cf68b3`

**新增功能**: 一鍵掃描並補足所有語系缺少的翻譯 key

**後端**:
- `LanguageService.sync_translation_keys()` — 掃描所有啟用語系翻譯檔，取得 key 聯集，自動補足缺少的 key
- 補值邏輯：
  - zh-CN 缺的 key → 從 zh-TW 用 opencc 繁簡轉換
  - zh-TW 缺的 key → 從 zh-CN 用 opencc 簡繁轉換
  - 其他語系 → 從基礎語系 en 複製
- `POST /api/sys_languages/sync-translations` API 端點

**前端**:
- SysProfilePage 語系設定區塊新增「語系翻譯同步補足」按鈕
- 執行後顯示各語系補足的 key 數量

**未來新增語系流程**:
1. 建立翻譯檔（AI 輔助翻譯或手動）
2. 資料庫新增語系記錄
3. 系統設定勾選啟用
4. 點「語系翻譯同步補足」→ 缺少的 key 自動用 en 填充
5. 管理者從語系管理介面逐一調整翻譯

### 8. 使用者下拉選單改為動態載入

**Commit**: `e431a34`

**修正前**: MainLayout 寫死 `my_profile`、`change_password`、`logout` 三個 func_code

**修正後**: 
- 從 `personal_function` 節點下動態載入所有子功能
- 依 `func_order` 排序顯示
- `logout` 功能前自動加分隔線
- 圖示和名稱從 system_functions 設定讀取
- 可在系統功能管理中自由新增/調整/排序個人化功能項目
