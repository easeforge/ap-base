## 一、登入問題排除（序言）

開發機首次登入遇到 `系統訊息：(ERR510005)JWT 解碼失敗` 的錯誤，追查發現：

- localStorage 殘留測試時手動設的無效 token
- axios 攔截器收到 401 後會清 token 並帶代碼到登入頁顯示

**→ 本機測試期間若需手動清狀態：** `localStorage.clear(); location.reload()`

順便驗證整條錯誤訊息鏈：後端 `raise_msg` → `to_env_code` → axios 攔截 → URL `?msg=CODE&p=PARAMS` → LoginPage 翻譯顯示。

## 二、訊息代碼系統（Phase 12）

### 編碼規則

```
{SYS|ERR|DAT} + 2碼分類 + 4碼流水 = 9 碼

SYS = 系統訊息（狀態、成功、提示）
ERR = 錯誤訊息（失敗、例外）
DAT = 資料處理（匯入匯出、驗證、批次）

分類區間：
  01~49  正式環境（簡潔、不洩漏細節）
  51~99  開發測試（含技術細節，正式碼 +50）
```

### 後端 helper（`app/core/message_codes.py`）

```python
from app.core.message_codes import raise_msg

# 不帶參數 → detail 為字串代碼
raise_msg(401, "ERR010001")
# → {"detail": "ERR010001"}（production）
# → {"detail": "ERR510001"}（development 自動切換）

# 帶參數 → detail 為 {code, params} 物件
raise_msg(401, "ERR010001", account="admin")
# → {"detail": {"code": "ERR510001", "params": {"account": "admin"}}}
```

### 前端 Toast（`contexts/MessageContext.tsx`）

```typescript
const { showSuccess, showError, showApiError } = useMessage();

showSuccess('SYS020001', { name: pageTitle });      // 綠色 toast
showError('ERR020003', { action: 'edit' });          // 紅色 toast
catch (err) { showApiError(err); }                   // 自動解析後端 detail
```

顯示格式：`系統訊息：(代碼)翻譯後說明`

### 代碼清單

| 類別 | 分類 | 正式 | 開發 | 用途 |
|------|------|------|------|------|
| SYS | 00 | 1 | - | 基準碼 |
| SYS | 01 | 3 | 3 | 認證成功訊息 |
| SYS | 02 | 4 | 4 | 通用 CRUD 成功 |
| SYS | 10 | 1 | 1 | 使用者操作成功 |

## 六、開發上的注意點

### 新增應用模組時

1. **錯誤回應**：不要寫 `raise HTTPException(detail="中文字串")`
   - 改用 `raise_msg(status, "ERR020001", entity="...", id=xxx)`
   - 通用錯誤用分類 02（`ERR020001~020007`）不需新建
   - 只有模組特定業務規則（如密碼政策）才建新代碼

2. **前端訊息顯示**：不要用 `alert()`
   - 成功：`showSuccess('SYS020001', { name: pageTitle })`
   - API 錯誤：`catch (err) { showApiError(err); }`
   - 表單驗證：`showError('ERR020006', { field, detail })`

3. **新增代碼的工具**：
   ```bash
   # 命令列單筆
   venv/Scripts/python tools/insert_message_code.py \
     ERR020099 "繁中說明" "简中说明" "English" --pair ERR520099

   # 或在 Python 程式呼叫
   from tools.insert_message_code import insert_message_code
   insert_message_code(code=..., translations=..., env=..., pair_code=...)
   ```

### i18n 翻譯資料流

1. 資料來源：`sys_languages.lang_data` JSONB 欄位
2. 後端啟動時 `LanguageService.sync_locale_files` 寫出到 `frontend/src/locales/*/translation.json`
3. 前端 i18next-http-backend 從 `/api/sys_languages/{lang}` 動態載入（公開端點）
4. 靜態檔案作為 fallback

**→ 要改翻譯必須改 DB**，不能直接改靜態檔（會被同步覆蓋）。
