## 二、架構設計

### 2.1 雙重保護模型

單純靠 License Key 擋功能還不夠安全（理論上可以 fork 然後改驗證邏輯）。
我們採「**License + EE 程式碼分離**」的雙保護：

```
CE repo（公開，MIT）
├── 授權驗證程式（公開，任何人可稽核）
├── 公鑰（嵌入）
└── 基底平台功能（完整可用）

EE repo（私有）
├── 繼承 CE（upstream sync）
└── app/ee/（商用功能程式碼，僅 EE 持有）

license.key（簽章文件，客戶付費取得）
└── 列出啟用哪些 features

啟用條件 = EE 程式碼 AND 簽章有效的 license.key
```

換句話說：
- 偷走 CE 程式碼：沒有 EE 模組，啟動不了 EE
- 偷走 license.key：沒有 EE 程式碼，啟動不了 EE
- 兩者都有：才會啟用（也就是買 EE 的合法客戶）

### 2.2 CE 包含什麼

| 類別 | 內容 |
|------|------|
| 基底功能 | 登入 / 使用者 / 組織 / 角色 / 權限 / 系統功能 / 通知 / i18n / 訊息代碼 / Toast |
| 驗證機制 | Ed25519 公鑰、簽章驗證邏輯、license 解析器 |
| Plugin 掛入點 | `register_router / register_startup / register_shutdown / register_menu` |
| 工具腳本 | `generate_license_keypair.py`（產 keypair）、`sign_license.py`（簽 license） |

### 2.3 EE 將包含什麼（後續 Phase）

| 功能 | 說明 |
|------|------|
| `app/ee/scheduler/` | cron 任務管理（Phase 2 優先做） |
| `app/ee/ai/` | OpenAI / Claude 整合，智能搜尋、翻譯、摘要 |
| `app/ee/sso/` | SAML / OAuth / LDAP 整合 |
| `app/ee/audit_report/` | 欄位級稽核、合規報表 |
| `app/ee/scheduling/` | 批次匯入、排程報表 |

## 四、簽發 License 的標準流程

### 4.1 一次性設定（**已完成**）

```bash
# 產生 keypair
cd Develop/backend
venv/Scripts/python tools/generate_license_keypair.py

# 將 public_key.hex 貼到 app/core/license.py 的 LICENSE_PUBLIC_KEY_HEX
# 私鑰上傳到 NAS
scp license_keys/private_key.pem porsche@10.1.0.254:/mnt/nas/production/secrets/ap-base/

# 刪除本機副本
rm -rf license_keys/

# Commit 並 push CE（公鑰部分）
git add LICENSE ARCHITECTURE.md app/core/license.py ...
git commit -m "feat(ce/ee): ..."
git push origin main
```

### 4.2 日後每位客戶購買時的簽發流程

```bash
# 1. 從 NAS 取私鑰到本機暫存
scp porsche@10.1.0.254:/mnt/nas/production/secrets/ap-base/private_key.pem /tmp/

# 2. 簽發
cd Develop/backend
venv/Scripts/python tools/sign_license.py \
    --private-key /tmp/private_key.pem \
    --customer-id CUST-xxxx \
    --customer-name "客戶名稱" \
    --features scheduler ai sso \
    --expires-days 365 \
    --max-users 100 \
    --output license.key

# 3. 立刻刪除暫存私鑰
rm /tmp/private_key.pem

# 4. 把 license.key 交付給客戶
# 5. 客戶放到 Develop/backend/license.key 然後重啟後端
```

## 六、Q&A 回顧

本次 session 過程中澄清的重要概念，歸納如下：

**Q：CE 是否也需要 license.key 保護？**
→ 不需要。CE 是 MIT 開源免費，license.key 只用來解鎖 EE 功能。
這也符合 GitLab / Sentry / Metabase 等主流雙軌模式。

**Q：為什麼 license 驗證程式碼要公開？**
→ 安全性來自**私鑰**而非**演算法**。公開反而方便社群稽核「沒有後門」，建立信任。

**Q：有人 fork CE 改掉公鑰怎麼辦？**
→ 他等於 fork 出獨立版本，跟原廠商用版不相容。MIT 允許這件事，我們也不管控。

**Q：私鑰怎麼保管？**
→ 存在生產伺服器 NAS 掛載區（CIFS 到 10.1.0.30），porsche 帳號 SSH 存取。
若私鑰外洩：須重新產 keypair → 更新 CE 公鑰 → 發布新版 CE → 舊 license 全數作廢。
